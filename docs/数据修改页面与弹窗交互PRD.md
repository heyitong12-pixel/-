# 数据修改页面 · 交互 PRD（含弹窗）

> 文档版本：v1.0　适用原型：`esl-app.html` →「数据修改」页
> 面向对象：开发、UI、测试
> 关联功能：刷图同步、消息中心
> 文档说明：描述「数据修改」页面的字段、编辑、提交，以及「影响确认」「刷图进度」「成功结果」三个弹窗的完整交互逻辑。

---

## 1. 功能概述

### 1.1 业务背景
- 一条**数据**（如「可乐 500ml 促销装」）可被**多台设备**（ESL 价签 / LCD 屏）绑定。
- 用户修改数据后，**所有绑定该数据的设备**都必须**同步刷图**，否则数据与设备屏幕内容不一致。

### 1.2 核心目标
1. 修改前明确告知影响范围，防止误操作引发大量刷图。
2. 修改后清晰反馈「保存 + 刷图」进度与结果。
3. 失败设备支持单条重试，保证数据一致性可补救。

### 1.3 页面入口
- 我的空间 → 金刚区「常用功能」→ **数据修改**

## 2. 数据修改页（主页面）

### 2.1 页面结构

```
┌────────────────────────────────────┐
│ 顶栏：数据修改                       │
├────────────────────────────────────┤
│ 【基本信息卡】                       │
│   数据 ID（只读）                    │
│   数据名称（可编辑）                 │
│   价格（可编辑，单位：元）           │
├────────────────────────────────────┤
│ 普通字段数据                        │
│   名称（可编辑）                     │
│   会员价（可编辑）                   │
│   条码（可编辑，12~13位）            │
├────────────────────────────────────┤
│ 图片字段数据                        │
│   主图（已上传，点击可替换）          │
│   图标（未上传，点击上传）            │
├────────────────────────────────────┤
│ 底部操作条： [取消]  [修改]          │
└────────────────────────────────────┘
```

### 2.2 字段定义

| 分组 | 字段 | 类型 | 是否可编辑 | 校验/说明 |
|------|------|------|-----------|----------|
| 基本信息 | 数据 ID | 文本（只读） | 否 | 系统生成，如 `20250812001` |
| 基本信息 | 数据名称 | 文本 | 是 | 必填 |
| 基本信息 | 价格 | 数字 | 是 | 必填，单位：元 |
| 普通字段 | 名称 | 文本 | 是 | 必填 |
| 普通字段 | 会员价 | 数字 | 是 | 选填 |
| 普通字段 | 条码 | 数字 | 是 | 12~13 位 |
| 图片字段 | 主图 | 图片 | 是 | 点击替换 |
| 图片字段 | 图标 | 图片 | 是 | 点击上传，未上传显示虚线占位 |

### 2.3 交互规则

| 元素 | 交互 |
|------|------|
| 输入框 | 获得焦点高亮边框（主色 #5b7cfa）；失去焦点恢复 |
| 主图/图标 | 点击弹出图片选择（相册/拍照）；图标未上传时显示「📷 上传」占位 |
| 取消按钮 | 返回上一页，不保存 |
| 修改按钮 | 触发「影响确认弹窗」（见 §3） |

### 2.4 校验
- 必填字段为空：点击「修改」时提示「请填写 XX」。
- 条码长度非 12~13 位：提示「条码需为 12~13 位数字」。

## 3. 弹窗 1：影响范围确认弹窗

### 3.1 触发
- 点击「修改」按钮且校验通过后弹出。

### 3.2 内容

```
⚠️
确认修改并同步？
此数据已绑定 20 台设备
修改后将自动同步刷图
预计耗时约 30 秒，期间请保持设备在线
[取消]  [确认修改]
```

### 3.3 字段
| 项 | 说明 |
|----|------|
| 绑定设备数 | 动态获取，如「20 台」；数字红色加粗突出 |
| 预计耗时 | 按设备数估算，如「约 30 秒」 |

### 3.4 交互规则
| 按钮 | 行为 |
|------|------|
| 取消 | 关闭弹窗，停留在修改页，不保存不刷图 |
| 确认修改 | 关闭确认弹窗 → 打开展开「刷图进度弹窗」（见 §4） |

### 3.5 状态说明
- **无绑定设备**：不弹此窗，直接提示「修改成功」并返回。
- **设备全部离线**：此弹窗可追加警告「有 X 台设备当前离线，可能无法同步」，需用户确认是否继续。

## 4. 弹窗 2：保存 + 刷图进度弹窗

### 4.1 触发
- 确认修改后弹出。

### 4.2 内容

```
正在保存并刷图…
[████████░░░░░░]       ← 进度条
12 / 20 台     预计 15 秒   ← 计数 + 剩余时间

货架B-01  8C:CE:4E:...:1A   ✓ 成功
货架B-08  8C:CE:4E:...:16   ✕ 失败
货架B-09  8C:CE:4E:...:17   刷图中
货架B-10  8C:CE:4E:...:18   待刷图
```

### 4.3 元素说明
| 元素 | 说明 |
|------|------|
| 标题 | 「正在保存并刷图…」 |
| 进度条 | 主色渐变填充，宽度随完成数增长 |
| 计数 | 「已成功数 / 总数 台」 |
| 剩余时间 | 按进度估算 |
| 设备列表 | 每台设备实时显示状态 |

### 4.4 设备状态与视觉
| 状态 | 文案 | 颜色 |
|------|------|------|
| 待刷图 | 待刷图 | 灰 |
| 刷图中 | 刷图中 | 主色蓝 |
| 成功 | ✓ 成功 | 绿 #2ec47b |
| 失败 | ✕ 失败 | 红 #e0574b |

### 4.5 交互规则
- 弹窗**不可关闭**（加载中状态，防中途操作）。
- 全部设备处理完成 → 自动关闭，弹出「成功结果弹窗」（见 §5）。

---

## 5. 弹窗 3：成功结果弹窗

### 5.1 触发
- 刷图进度弹窗全部处理完成后弹出。

### 5.2 内容（全部成功时）

```
✅
修改成功 · 刷图完成
20 台设备已同步
[查看刷图详情]  [返回]
```

### 5.3 内容（部分失败时）

```
✅
修改成功 · 刷图完成
18 台成功 · 2 台失败
[有 2 台设备刷图失败，可点击「重试」重新下发]

货架B-08  ✕ 失败  [重试]
货架B-16  ✕ 失败  [重试]

[查看刷图详情]  [返回]
```

### 5.4 交互规则
| 元素 | 行为 |
|------|------|
| 成功/失败汇总 | 顶部摘要，失败数字红色强调 |
| 失败横幅 | 有失败时显示，引导用户重试 |
| 失败设备行「重试」 | 点击后该设备状态变为「✓ 已同步」（模拟），若仍失败提示「重试失败，请检查设备」 |
| 查看刷图详情 | 关闭弹窗 → 跳转「刷图进度」页查看全部设备明细 |
| 返回 | 关闭弹窗 → 返回上一页（数据列表/首页） |

### 5.5 全部失败极端情况
- 文案改为「修改已保存，但 X 台设备均刷图失败，请检查设备后重试」。
- 不自动返回，引导用户「重试」或「查看详情」。

## 6. 完整流程状态机

```
[数据修改页]
   ↓ 点击[修改]（校验通过）
[弹窗1：影响确认]
   ├─ 取消 → 回到修改页
   └─ 确认修改 →
[弹窗2：刷图进度]（不可关闭）
   └─ 全部完成 →
[弹窗3：成功结果]
   ├─ 重试失败设备 → 单条更新为成功（或再失败提示）
   ├─ 查看刷图详情 → 刷图进度页
   └─ 返回 → 上一页
```

---

## 7. 异常与边界

| 场景 | 处理 |
|------|------|
| 数据无绑定设备 | 不弹确认窗，直接「修改成功」返回 |
| 设备全部离线 | 确认窗追加离线警告 |
| 部分设备失败 | 结果页列失败设备 + 重试 |
| 全部失败 | 结果页突出「均失败」，引导重试/检查 |
| 修改保存成功但刷图延迟 | 结果页提示「已保存，刷图进行中，可到消息中心查看」 |
| 用户在确认窗取消 | 不保存、不刷图，停留修改页 |
